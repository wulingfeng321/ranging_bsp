# 48 kHz 采样与测距

16 kHz 基线提交：`464cb35`。开发分支：`feat/audio-48khz`。

## 实现

默认 `APP_AUDIO_SAMPLE_RATE=48000`，两板使用相同配置。保留 `16000` 编译选项供回归。
LEGACY 的声学波形仍为 2–6 kHz、32 ms 上/下/上扫频，间隙 8 ms，签名周期 500 ms。
模板从 512 点扩为 1536 点，三脉冲起点间隔从 640 点扩为 1920 点。
WIDE 的模板和检测窗口也按采样率适配，默认仍选择 LEGACY / JOINT2。

- 每次 DMA 回调接收 768 帧，仍对应 16 ms；DMA 双半缓冲占 6144 字节。
- 音频时间模型拟合约 20833.333 ns/样点；时间换算保留分数，避免将样点周期截成整数。
- 所有测距窗口、扫描步长、候选搜索范围和 250 ms 检测间隔保持原有物理时间尺度。
- 测距使用完整 48 kHz PCM；仅 LCD 波形预览每三点取一点，保持原 160 ms 显示窗口和显示负载。
- 粗搜索每 187.5 us 检查一次，每次只计算 512 对样点；通过后使用全部 1536 点精匹配。
  粗门限仍是候选筛选，最终峰位置和质量全部由 48 kHz 完整相关决定。
- 单通道环形缓冲扩大到 32768 点；无阻塞式整段录制步骤，网络同步持续运行。
- 48 kHz 测距协议版本为 3，16 kHz 为 2，防止混用固件产生测距结果。
- 新增每秒 DSP 耗时比例、最长一次 DSP 调用时间、当前音频积压显示。

IAR 链接报告 A 板约 159235 字节 readwrite 数据（另有 320 字节绝对地址数据），
链接成功，没有越过当前内存区域。LCD 和 DMA 使用已有 SDRAM 地址规划。

## 负载评估与实时处理选择

在实际 C 检测器中统计完整 15.5 秒测试 WAV 的相关乘加次数（15 个签名）：

| 配置 | 总相关乘加 | 最繁忙一次扫描（含候选提取） |
| --- | ---: | ---: |
| 16 kHz | 34113536 | 82432 |
| 48 kHz | 42027008 | 617984 |

该测试的总相关工作量为原来的 **1.232 倍**，因此先保留实时处理。
签名附近的峰值工作量更大，表中计数不包括显示、网络等开销，也不是 Cortex-M7 周期测试。
现场噪声、持续音调和混响会改变门限通过次数，仍需看板上耗时与积压。

屏幕诊断轮换新增：

- `DSP`：最近约一秒中 DSP 调用的耗时比例，含被中断抢占的时间，不是整机 CPU 利用率。
- `MAX`：启动以来最长一次 DSP 调用，单位 us。
- `BK`：当前积压，单位 ms；JOINT2 的完整窗口本身就占 144 ms，不能要求它为零。
- `D/G/O`：仍用于检查丢块、回调间隔异常、缓冲溢出。

上板若 `O` 增加或 `BK` 持续上升，应停止把结果用于精度结论，再进一步优化或采用整段缓存。
没有实施“录完 10.5 秒后分析”：那还需要共同的录制批次、分段时基记录、冻结录制时的同步映射，
以及适配目前 1.5 秒事件过期规则；不能只把当前 DSP 调用推迟 10.5 秒。

## 验证

- IAR LEGACY / JOINT2 A、B 两板编译链接：均 0 错误、0 警告。
- 16/48 kHz A、B 主机状态机：候选通信、重传、配对歧义、同步频漂换算、连续采样与错误重置通过。
- 两种采样率音频时基拟合：频漂、延迟回调、重复锚点、启动/重置通过。
- 原 16 kHz 联合峰回归通过，包括 13/18 cm 竞争解拒绝和编码检查。
- 48 kHz：768 个整数窗口位置全部检出；完整 WAV 四种起始偏移均检出 15 个签名。
- 无回声、无噪声的 200 个双方向分数延迟案例：最大时间误差 622 ns，约 0.214 mm。
  这只覆盖所测合成输入，不代表实机精度，也不覆盖所有窗口边界和真实频响。
- 静默、噪声、持续纯音拒绝；单段回声不会产生测试所定义的大幅错误有效延迟。
- WIDE 48 kHz 模板和扫描边界的 52 个对齐用例通过；未将其作为本轮推荐上板配置。

本次没有烧录或进行硬件负载/精度验收。

## 构建与测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_range_profiles.ps1 -Profiles legacy -JointPeaks -SampleRate 48000
powershell -NoProfile -ExecutionPolicy Bypass -File tools/tests/run_host_tests.ps1
```

脚本默认使用本机 IAR 8.2 和 VS 18 的工具路径；其他电脑分别传入 `-IarBuild` / `-VcVars`。
主机产物写入系统临时目录，不写入工程目录。固件文件名包含采样率，方便区分。

## 使用

1. 两板分别烧录：
   - `EWARM/ranging_bsp/Exe/ranging_legacy_joint2_A_48000Hz.hex`
   - `EWARM/ranging_bsp/Exe/ranging_legacy_joint2_B_48000Hz.hex`
2. 确认屏幕为 `JOINT2 48k`，并等待 `SYNC READY`、`AT:OK`。
3. 播放 `tools/test_audio_chirp_48k_repeat.wav`：48 kHz、单声道、PCM16，总长 15.5 s。
   前 10.5 s 包含 15 个签名，末尾 5 s 静默。保留 130 mm、相同音量和同一播放设备。
4. A/B 两侧各完整播放一轮，记录结果和 `DSP/MAX/BK`、`D/G/O`、`AM/IC` 的增量。
   静默结束后再开始下一轮。

生成音频与模板：

```powershell
python tools/sound_make.py --sample-rate 48000 --output tools/test_audio_chirp_48k.wav
python tools/sound_make_repeat.py --sample-rate 48000
python tools/make_range_template.py --sample-rate 48000
python tools/make_wide_audio.py --sample-rate 48000
```

WIDE 使用 `tools/test_audio_wide_48k_repeat.wav`。旧 16 kHz 文件保留原名供基线对照。
采样由 `MicScope_Init()` 调用 BSP 配置 SAI/WM8994，本次无需额外修改 CubeMX 的 SAI 选项。
