# A/B 双板 UDP 通信首版
上板验证：开发者确认 A/B 两板已能正常通信。
拔插恢复与长期稳定性仍待验证。
## 目的与范围

实现 P0/P1 的角色配置、握手、心跳、测试数据回传和掉线恢复。仍保留 LCD、麦克风和 ping，不把测试计数当成距离，不实现时间同步或测距。已有工作区网口驱动、IAR 内存布局与个人 IDE 修改均保留；未提交或推送。

## A/B 只改一处

打开 `Core/Inc/app_board_config.h`，修改默认行：

```c
// A 板：
#define APP_BOARD_ROLE APP_BOARD_A
// B 板：
#define APP_BOARD_ROLE APP_BOARD_B
```

保留其中一个定义；当前源码默认 B。也可以在 IAR C/C++ Compiler 的预处理宏中定义 `APP_BOARD_ROLE=1`（A）或 `APP_BOARD_ROLE=2`（B）；外部定义优先于头文件默认值，不能配置后忘记移除。每次切换后重新 Make、下载、运行。

| 项目 | A | B |
|---|---|---|
| 本机 IP | 192.168.10.10 | 192.168.10.11 |
| 对端 IP | 192.168.10.11 | 192.168.10.10 |
| MAC | 02:00:00:00:00:0A | 02:00:00:00:00:0B |
| UDP 本地/目标端口 | 5000 | 5000 |

掩码均为 255.255.255.0。`lwip.c` 在用户区按角色覆盖最后一个 IP 字节，`ethernetif.c` 在用户区设置对应 MAC；不要再单独修改生成区的 `.10`/`.11`。两个角色是本地约定，只有这两块板使用，扩展到更多板必须另行分配唯一地址。

## 改动与调用约定

- 新增 `app_board_config.h`、`app_net.h/.c`，IAR 加入 `app_net.c`。
- `AppNet_Init()` 在 `MX_LWIP_Init()` 后调用一次，分配 UDP PCB，绑定 5000，注册接收回调。
- `AppNet_Process()` 在主循环中紧随 `MX_LWIP_Process()`，使用毫秒差值调度，不调用延时等待。
- 接收回调运行在 LwIP 主循环上下文，只解析、更新状态和短消息应答，不绘图。接收 pbuf 在回调中释放；发送使用复制后的 PBUF_RAM，发送接口返回后释放调用方引用。
- 初始化通过片内 RNG 生成 64 位随机会话 ID（不是安全认证）；使用当前已配置的 PLLSAIP 48 MHz 时钟，读取最长等待 20 ms，之后关闭 RNG。失败明确显示 ERROR，不使用固定会话号冒充重启识别。未改动音频采样率、DMA、MPU 或时钟树。
- 网络状态由 `DrawDashboard()` 在现有 LCD 主循环刷新；右上角如 `B NET ONLINE OK:12`。ONLINE 为握手成功且未超时，OK 为收到正确 TEST_ACK 的累计次数，不是同步锁定状态或测量结果。

## 线上格式 v1

固定 32 字节，所有多字节整数均为大端，逐字节编码，不直接复制 C 结构体。

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | ASCII `RNG1` |
| 4 | 1 | 版本 1 |
| 5 | 1 | 类型：1 HELLO、2 HELLO_ACK、3 HEARTBEAT、4 TEST、5 TEST_ACK |
| 6 | 1 | 发送角色：1 A、2 B |
| 7 | 1 | 报文长度 32 |
| 8 | 8 | 发送方启动会话 ID |
| 16 | 4 | 序号；ACK 回显请求序号 |
| 20 | 8 | 目标会话 ID；HELLO 为 0，其余必须匹配接收方会话 |
| 28 | 4 | TEST 数据/原样应答；其他消息为 0 |

初期 TEST 数据为 `请求序号 XOR 0x12345678`。发起方核对会话、序号和数据后才增加 OK 计数。协议还未包含业务音频事件、距离或同步时间。

只接受指定对端 IP、UDP 5000、相反角色、正确版本和长度。HELLO 每秒重试；握手完成后每秒发送 HEARTBEAT 和 TEST。3 秒没有有效对端通信则离线并重新握手；PHY 链路断开时立即清理会话状态。TEST 超过 1 秒记超时，下一周期发送新测试；重复 TEST 可重发 ACK，但不重复计作新数据。ACK 不再触发 ACK。

## 烧录与验收

1. 两块板均更新本次协议源码，分别选择 A/B；仅另一台能 ping 通不代表支持本协议。
2. 两板接入同一交换机，上电并持续运行；电脑可接同一交换机，设为 192.168.10.20/24。
3. 两屏应分别显示 A/B，随后 ONLINE，OK 计数持续增长；验证电脑可 ping `.10` 和 `.11`。
4. 拔线：断开的本板可立即 WAIT，另一板最迟约 3 秒 WAIT。插回等待链路协商和握手，确认恢复；分别复位 A、B 验证会话重建。
5. 记录至少一段持续运行时长、OK/超时数、音频是否持续采集，再决定 P0/P1 是否验收完成。

在 IAR Watch 中查看 `appNetStatus`：`initError`（0 成功，-1 RNG，-2 PCB 分配，-3 bind）、`online`、`tx/rx`、`rejected`、`testAck`、`testTimeout`、`lastRttMs`、`txErrors`。RTT 为软件毫秒计时，不能证明微秒同步；计数是累计值，不直接等于线上的丢包率。
