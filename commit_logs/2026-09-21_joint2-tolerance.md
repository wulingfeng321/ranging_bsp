# JOINT2：修复候选峰提取过严

用户实测 JOINT1 经常没有 PEAK 或提示 PEAK 不确定，偶尔能测准。本版继续使用旧音频，
保持三候选通信、联合配对及统计流程，针对已复现的候选丢失修改 DSP。

JOINT1 要求三段脉冲的局部最大值都在同一个整数 lag。以合成的连续旧扫频波形测试，
签名从 100.4 样点开始，仅让中间一段多延迟 0.2 样点，旧版就返回 0 个候选。
两板即使具有相同的这种微小畸变，也在联合比较之前被拒绝。

JOINT2 先找三段联合相关的局部峰，再允许每一段在附近 ±1 样点内独立寻找自己的局部峰，
分别插值并上传真实位置。没有把三段的不同位置强行改成相同值。
多个联合起点若收敛到同一组三段峰，则合并，避免重复候选挤占三个名额或触发溢出。

以下保护未放宽：每段相关质量门槛、跨板三段时间差极差 40 us、竞争解相差 60 us 且评分
达到最佳 85% 时拒绝、强候选溢出拒绝、绿色统计的 100～200 mm 范围。
因此真正无法确定的观测仍会提示 PEAK UNCERTAIN；不承诺每次播放都输出数字。

曾试验以相关功率重新解释歧义评分，但回声回归出现错误的有效延迟，已撤回该修改。
最终版本仍使用 JOINT1 的评分与歧义阈值，仅调整候选提取和重复候选合并。

## 验证

- 上述 +0.2 样点和三段偏移 [0,+0.2,-0.2] 用例，JOINT1 为 0 候选，JOINT2 可正常联合配对。
- 256 个整数对齐、6 个真实分数延迟、旧 repeat 文件 15 次签名检测通过。
- 模拟单段较强回声仍得到正确结果或拒绝，没有放过先前覆盖的明显偏移。
- 13/18 cm 竞争解仍被拒绝；时间差不一致、候选溢出及负方向测试通过。
- A/B 候选通信、重传、乱序、连续采样及错误重置继续由 `test_joint_fsm.c` 验证。
- A/B 主机状态机测试通过；IAR 两板固件均编译链接通过，0 错误、0 警告。

## 使用

两板分别烧录 `EWARM/ranging_bsp/Exe/ranging_legacy_joint2_A.hex` 和 B 对应固件，确认 `RANGE JOINT2`。
仍播放 `tools/test_audio_chirp_repeat.wav`。原 JOINT1 固件文件不覆盖，方便对照。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_range_profiles.ps1 -Profiles legacy -JointPeaks
```

本修改已通过主机模拟，不等于解决了实测中所有拒绝原因。若仍频繁不确定，应记录屏幕 PK、AM、IC、DS
及音频丢块计数，进一步区分候选缺失、三段时间差不一致和竞争解，不能仅凭提示继续放宽阈值。
