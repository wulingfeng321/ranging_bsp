# 移除扫描线，增加候选测试音触发保持

- 日期：2026-09-17
- 编写：Codex 协助实现；实际提交作者以 Git 记录为准。
- 开发基线：50c5c4c 及未提交的覆盖扫描、README/交接日志改动。
- 状态：编译、主机逻辑测试通过；2026-09-17 开发者确认上板效果达到预期。

## 功能与关键文件

- `Core/Src/app_mic_scope.c` 移除黄色扫描线和扫描前方 4 像素间隙，保留亮暗区分覆盖轮次。
- `Core/Inc/mic_scope_trigger.h` 增加调试用候选检测：16 kHz PCM，以 4 ms 块估计去直流后的平均绝对幅度和过零次数，以 1 ms 步长搜索 32/8/32/8/32 ms 的 Up–Down–Up 趋势和两个静音间隔。任一本地通道满足条件即可触发，两路同时保存。
- `Core/Inc/app_mic_scope.h` 新增 `MIC_SCOPE_HOLD_MS=2000U`，单位毫秒；设为 0 禁用保持。`MIC_SCOPE_TRIGGER_MIN_LEVEL=128U` 是有效段平均绝对 PCM 幅度下限，不是 dB。
- 候选检测在主循环执行，ISR 仍负责数据搬运，仅额外累计扫描回绕次数。
- 检测到候选后保存按时间排列的完整 160 ms 双通道快照。等待检测时所在扫描轮结束，再展示并保持候选快照，避免跨屏接缝把测试音分成两半。
- 保持期间继续 DMA 采集、错误监视、距离状态和过期处理。保持结束后恢复实时显示，等待 160 ms 后重新允许触发，避免立刻复用旧窗口。
- 屏幕增加 `WAVE LIVE`、`TRIGGER: WAIT END`、`WAVE HOLD` 状态。保持的双通道波形使用亮色显示；其幅度比例来自同一份快照，因此保持时稳定。
- 新增快照约占 10240 字节静态内存，无新增固定 SDRAM 地址或中断源。

## 接口边界与上板验收

这是一项调试触发启发式，不是精确模板匹配；可能漏检或误触发，也不具备可用于测距的时间戳。UI 保持操作不改变音频采样时钟，不能作为未来两板同步机制。当前两条波形仍来自同一板。

上板后播放 tools/test_audio_chirp.wav，观察状态从 LIVE 到 WAIT END 再到 HOLD；波形应保持约 2 秒，距离区仍可更新，随后恢复扫描。静音或普通声音下检查误触发；声音很弱时可尝试降低幅度门限，混响明显时需要进一步改进检测。若需要精确事件识别和到达时间，应后续采用统一模板与样点时间基准。

保持画面是触发时保存的时间窗，不是等待轮结束那一刻的原始覆盖画面，这是为了保留跨扫描边界的完整测试音。160 ms / 40 ms 的显示窗口与刷新间隔保持不变。
