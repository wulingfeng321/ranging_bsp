# 指定 Up–Down–Up 音频双板测距（实验版）

## 目的与边界

在已验证的双板 UDP 通信基础上，连接「硬件时间戳 → 时钟映射 → 连续音频模板检测 → 同事件配对 → 两屏结果」。保留原来的候选触发/波形保持，但测距有独立检测器，保持显示不停止检测或网络。

这是待上板验证的测距实现，不是课程精度验收证明。没有实现 GPIO 整秒验证脉冲、现场交互温度设置、持久化单点标定或同步波形。16 kHz 与现有音频/显示内存配置保持不变。

## 固件与使用

- A `.10`、B `.11` 均需更新本次固件。保留原有 `APP_BOARD_ROLE` 开关；提交基线实际默认 A，本次交付最终也恢复 A。
- 输出：`EWARM/ranging_bsp/Exe/ranging_chirp_A.hex/.out` 与 `ranging_chirp_B.hex/.out`。不要使用之前只有 UDP 测试功能的旧 HEX。
- 两板接同一交换机，等待 NET ONLINE，再等待 SYNC READY，首次测试再等约 2 秒让音频样点周期估计稳定。READY 表示通过内部拟合门限，不表示已达到 ±10 us 验收指标。
- 每块板固定使用本地 L 麦克风（`APP_RANGE_CHANNEL=0`），测量距离取两块板对应麦克风开孔之间。两板朝向尽量一致。
- 声源、两块板共线，声源在线段外侧，距近板约 0.5–1 m：`声源 → A → B` 或 `A ← B ← 声源`。先以约 0.5 m 间距开发测试，避免混响强、削顶或音量过小。
- 用手机/电脑播放 `tools/test_audio_chirp.wav`。2.5 秒内含 5 次签名；如果检测成功且配对，距离会自动更新。两屏显示 ESTIMATE 和 A SIDE/B SIDE；近零/时间差小于同步不确定性时 SIDE ?。
- Q 是三段归一化相关系数的最低值乘 1000；EVT 是本板完整签名检测次数。SYNC 后的微秒数仅为时钟模型指标，不包括音频链路延迟或声学误差。
- 无新有效结果时 5 秒过期；断线、失锁、音频流异常清除本地有效结果。重复网络应答不延长旧结果有效期。

## 配置与公式

`Core/Inc/app_board_config.h` 新增：

```c
#define APP_RANGE_PORT 5001U
#define APP_TEMPERATURE_DECI_C 200 // 20.0 摄氏度，手动填现场空气温度
#define APP_RANGE_BIAS_NS 0LL     // 已标定的 B-A 差分固定延迟，纳秒
#define APP_RANGE_CHANNEL 0U     // 两板对应物理参考麦克风；0=L，1=R
```

两板除角色之外使用相同设置。`delta = T_B - T_A - bias`，`c = 331.3 + 0.606*T` m/s，`D = c*abs(delta)`，不除以 2。delta 正为声源 A 侧，负为 B 侧。初版只接受时间差绝对值不超过 20 ms、计算距离不超过 5 m，不承诺该范围内精度。

标定偏置需要已知距离、温度和声源侧，多次采集后估计 `bias = 平均原始时间差 - 有符号真值距离/c`。不能用一次肉眼读数证明精度；当前仅提供编译配置，没有实现标定向导、自动保存或校准有效性管理。

## 时间戳与同步

- `range_clock.c` 直接配置 F746 ETH PTP 时钟，HCLK 必须为 200 MHz，粗更新每周期 5 ns，十进制秒进位，接收所有帧的硬件时间戳。配置超时或时钟不匹配时失败，禁止软件时间戳替代。
- 依据 ST [RM0385](https://www.st.com/resource/en/reference_manual/dm00124865.pdf) 的 ETH 时间戳寄存器配置。本实现使用硬件计数器，但协议是私有双向交换，不是完整标准 PTP 协议栈。
- `ethernetif.c` 在阻塞发送结束时读取最后一个 TX 增强描述符的 DESC6/7；接收沿用 HAL 从 RX 描述符保存的时间戳。当前 HAL 的 `HAL_ETH_PTP_GetTxTimestamp` 读的是 DESC0/1，故没有调用该入口。
- 发送前要求 ARP 已解析，避免误把 ARP 请求或延迟发送的 UDP 当成本次请求的 TX 时间戳。
- B 每约 100 ms 发请求，记录 b1；A 硬件接收 a2，回复硬件发送 a3，另发 FOLLOW 携带 a3；B 保存回复硬件接收 b4。
- `(b1-a2+b4-a3)/2` 估计 B-A 偏移；`(b4-b1)-(a3-a2)` 估计往返链路延迟。拒绝 RTT<=0、>500 us 或比当前最小值大 20 us 的样本。最多 16 点拟合偏移和频率漂移，不跳变硬件时钟。
- 至少 8 个样本、拟合最大残差<=10 us、频差<1000 ppm 时 READY。显示指标为最大残差加最小 RTT/2，仅用于保守观察网络时钟，不能当作整个测距误差上界。
- 1.5 秒没有合格更新就失锁。会话/同步代次改变后清除旧事件，避免失锁前后时间映射混用。未接入 TIM5，音频和网络均引用同一个本地 ETH PTP 时基。

## 音频与检测

- `tools/make_range_template.py` 从实际 WAV 的第一段上扫和下扫提取 512 点模板、去直流，生成 `Core/Inc/range_template.h`，记录原文件 SHA256。生成脚本仅依赖 Python 标准库。
- 音频 DMA 回调入口读取本地 PTP 时间，复制所选通道到独立 8192 点环形缓冲，维护 64 位样点序号。回调间隔异常/缓冲追赶失败会丢弃窗口并计数，不跨缺口测距。
- 用约 64 个 DMA 半缓冲的时间跨度估计实际样点周期。以样点编号和最近 DMA 边界回溯检测峰时间，不用检测函数完成时刻。
- 主循环分片搜索完整 32/8/32/8/32 ms 签名；三段相关系数均需>=0.45，两个间隙能量受限，并对第一段峰附近做三点插值。阈值是开发默认值，需要真实录音评估。
- 避免两点搜索步长导致 4 kHz 中心频率波形的奇偶样点漏检，使用三点粗搜及局部逐点细搜。极性反转不影响检测。
- 同一次签名检测后至少间隔 4000 样点才再报事件；500 ms 重复播放可连续检测。
- 移除显示快照复制期间的整段关中断，改为 DMA 计数变化时放弃该次显示帧，减少音频时间锚点被显示代码延迟的风险。
- DMA 中断时间仍含中断延迟、SAI FIFO 和 codec 固定延迟；这不是 ADC 精确采样硬件锁存。模板峰可能受声学路径和设备频响偏移，不保证最早直达声。此部分需示波器/录音和已知距离实测校准。

## UDP 测距协议

原端口 5000 的 RNG1 握手/心跳不变。新端口 5001 使用固定 72 字节 `RAN2` 消息，所有多字节值大端：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 4 | RAN2 |
| 4..7 | 各 1 | 版本 2、类型、发送角色、长度 72 |
| 8、16 | 各 8 | 发送会话、目标会话 |
| 24、28 | 各 4 | 序号、同步代次 |
| 32、40、48、56、64 | 各 8 | 类型相关的五个无符号值 |

类型 1 REQ；2 RESP（a2）；3 FOLLOW（a3）；4 STATE（是否锁定、时钟指标 ns）；5 EVENT（统一到达时间 ns、质量）；6 RESULT（整数毫米、方向 0/1/2、质量）；7 ACK（确认的消息类型）。保留字段当前发送 0。

A/B 各保留最多 4 个事件，A 按统一时刻在 ±20 ms 内配对，事件最长等待 1.5 秒。500 ms 周期的不同声波不会仅按各自序号配对。A 计算唯一结果，向 B 发布。事件/结果每 200 ms 重试，最多约 1 秒或被更新结果替代；接收端按 ID 去重并应答。丢包仍可能导致个别事件缺失，需实测。

## 调试与验证

观察 `appRangeStatus`：events/rejected/audioDrops/syncSamples/syncErrorNs、locked/valid、distanceMm/quality/direction/results。error=-1 PTP 初始化失败，-2 测距 UDP 初始化失败，-3 曾发生同步超时，-4 曾发生音频缺口；后两项保留作诊断，不代表永久故障。

观察 `rangeTxStampSerial` 是否增长、`rangeRxTimestamp` 是否为非零递增硬件时间。只有 NET ONLINE 但 SYNC 一直 WAIT 时，应先检查这两个时间戳、B 的 syncSamples，不要用软件时间戳强行标记已同步。

主机测试：

- `test_range_math.py` 调用实际 C DSP/同步函数，使用真实 WAV，覆盖起始位置、音量、反相；拒绝静音、噪声、单音、错误签名；验证时钟偏移/40 ppm 漂移和延迟异常剔除、距离方向计算。
- `test_app_range.c` 执行实际 A/B 状态机，覆盖配对、重发去重、旧同步代次、超时失锁、断连、连续两次音频检测和音频缺口。
- 原 UDP 通信主机测试作回归。
- IAR A/B 两角色编译链接均为 0 错误、0 警告；源码恢复基线角色 A 后再次构建通过。音频检测环形缓冲 16 KiB、检测窗口 4 KiB 位于普通 SRAM，网络 RX 池仍在 0x20040000，描述符仍在 0x2004C000/0x2004C0A0，8 KiB 栈位于 DTCM，链接未重叠。没有进行硬件实测、GPIO 秒脉冲验证、实测误差或静默 60 秒验收。

下一步上板记录 0.5 m 等已知距离的多次结果、方向、Q、同步指标与 audioDrops；先排除固定偏置、丢样、反射峰和播放设备影响，再做 48 kHz 升级及课程指标验收。
