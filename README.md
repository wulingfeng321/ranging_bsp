# ranging_bsp · 双开发板声学测距

更新日期：2026-10-02。

基于两块STM32F746G-DISCO，通过以太网建立统一时间基准，采集声音并交换到达时刻，在板端完成测距、声源侧判断、波形显示与四麦方向估计；测量数据可保存到A板SD卡供PC离线分析。

## 1. 整体目标

面向嵌入式系统课程设计，实现全部基础部分、提高部分(1)/(3)/(4)/(6)，以及附加部分的数据存储与结果导出、声源定位。

| 范围 | 目标 |
| --- | --- |
| 基础(1)～(5) | 双板自动联网与时间同步、声音到达时刻检测、离线自动测距及A/B声源侧判断、环境适应与抗误触发、手动声速温度补偿 |
| 提高(1)/(3)/(4)/(6) | 自动声速温度补偿、击掌测距、测量质量指示、同步波形显示 |
| 附加 | 标准音频测距的双板原始数据及测量结果保存/导出；两板四麦声源方向与方位角估计 |

基础验收关键指标包括：经交换机联网后30秒内同步，连续10次GPIO整秒脉冲偏差不超过±10 μs；0.20～2.00 m内单次测距误差不超过±10 mm，至少10次重复测量标准差不超过2 mm，同次两屏距离差不超过1 mm，播放标准音后2秒内显示距离及方向。全部指标和实现差距见[PROJECT_STATUS第2节](PROJECT_STATUS.md#2-总体目标与验收差距)。

标准测距观测的是两板声程差。声源应在两板外侧，距近板指定麦克风0.5～1 m，与两板指定L麦克风近似共线；真值按麦克风开孔间距测量。测量与显示不依赖PC辅助，PC用于声音播放或事后解码。当前定位扩展输出粗方向及方位角，尚未输出声源距离或二维坐标。

## 3. 工程结构

| 路径 | 职责 |
| --- | --- |
| `Core/Inc/app_board_config.h` | A/B角色、固定48 kHz采样约束、音频方案及温度/统计默认配置 |
| `Core/Src/main.c` | 初始化、MPU配置与主循环调度 |
| `Core/Inc/board_memory.h` | 应用SDRAM地址、容量和编译期边界检查 |
| `Core/Src/app_wave.c` | 单音周期拟合、共享周期状态及波形窗口插值 |
| `Core/Src/board_audio.c` | BSP音频启动、DMA回调派发与采集异常状态，独立于UI |
| `Core/Inc/app_wire.h` | 网络和保存协议共享的显式大小端字节编码 |
| `Core/Src/app_net.c` | 网络连接、身份与会话管理 |
| `Core/Src/range_clock.c`、`range_sync.c` | 硬件时基、GPIO同步检验脉冲与时钟模型 |
| `Core/Src/app_range.c`、`range_dsp.c` | 音频时基、标准检测/配对/统计、测量协议及各页数据处理 |
| `Core/Inc/range_peak_pair.h`、`range_batch.h` | 联合候选配对及批次统计 |
| `Core/Inc/clap_dsp.h`、`position_dsp.h` | 击掌瞬态检测、定位专用扫频检测与方向计算 |
| `Core/Src/app_mic_scope.c` | 四页绘图、触摸、详情视图与显示调度 |
| `Core/Src/app_capture.c`、`capture_sd.c` | 双板录音保存事务及FatFs/SDMMC DMA驱动 |
| `LWIP/`、`FATFS/`、`Drivers/`、`Middlewares/` | 网络、文件系统与芯片/库依赖 |
| `ranging_bsp.ioc`、`EWARM/ranging_bsp.ewp` | CubeMX及IAR工程配置 |
| `tools/` | A/B角色构建及RNG解码等PC工具 |
| `tools/audio/`、`tools/audio/generated/` | 统一音频生成/显式模板导出，及按用途/采样率/时长命名的播放音与回归输入 |
| `tools/tests/` | 标准状态机/时基、界面/击掌/定位/波形及录音保存主机回归 |
| `commit_logs/` | 功能实现与验证记录、界面预览和历史交接资料 |

工程使用IAR EWARM 8.2，采用主循环状态机，无RTOS；头文件默认角色为B，角色构建脚本显式生成A/B配置。板级BSP及组件已收录在`Drivers/BSP/`，字体位于`Drivers/Fonts/`，当前固件构建不再引用仓库外的上层BSP/字体目录；来源、收录范围及本地路径适配见[依赖说明](Drivers/DEPENDENCIES.md)。

## 5. 交接规范

1. 开始工作前确认当前分支、提交与工作区改动，保留同伴或用户未提交内容；区分源代码版本和板上固件版本。
2. 功能修改在`commit_logs/`记录目的、关键文件/接口、单位与时基、资源影响、验证、未验证项和下一步，并更新CHANGELOG索引。PROJECT_STATUS只记录实现/固件/验证状态，操作与参数变化更新USER_MANUAL。
3. ISR保持必要的PCM/锚点搬运、计数及定位两点平均；检测相关、绘图、写卡和长计算放在主循环。修改DMA/SDRAM/Cache/MPU/时钟/中断时核对采集连续性、处理积压与网络服务。
4. 接口说明调用上下文、缓冲归属和生命周期。`LOCAL MIC L/R`均为本板麦克风，标准测距使用L；`MicScope_SetDistanceMm`接收毫米，只在新结果到达时发布，重绘或重复包不延长旧结果寿命。温度读取回调使用新鲜有效缓存，不阻塞等待转换。
5. 两板的协议版本、采样率和模板保持兼容，温度/页面由可靠设置协议同步。CubeMX重新生成后检查main用户区、BSP句柄、SD DMA/IRQ与IAR源文件列表，保留工程内依赖及LCD字体路径适配；`ethernetif.c`按用户约定通过Git恢复。
6. 固件修改编译相关A/B配置并进行针对性验证；区分主机通过、编译通过、下载校验、实机功能反馈和完整验收。已有回归入口为`run_host_tests.ps1`、`run_scope_tests.ps1`、`run_capture_tests.ps1`，位于`tools/tests/`；执行前核对工具及输入依赖。
7. 保存失败轮和原始数据，记录音频/固件版本、真值参考点、几何摆放、播放设备/音量、温度及批次。目录号、文件头标识或文件系统日期不能单独代表固件或采集版本。
8. 提交前审阅差异，不混入个人IDE状态、临时工程、构建产物或大体积原始录音。共享`.ioc/.ewp/.ewd`变更说明原因；Git提交、推送、烧录和测试结果分别记录，归档分支实验不直接视作当前基线。

按用户2026-10-02授权，后续固件改动在编译及必要检查通过、开发板已连接时，直接执行对应A/B烧录，无需再次单独确认；烧录前核对角色、探针和产物，启用下载校验，实机反馈单独记录。
